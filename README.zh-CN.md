# bmo-voc

客户之声收集箱：客户发给开发者的缺陷报告和建议，以及开发者阅读这些内容的服务。登录控制台且不是平台管理员的人可以附上
截图和文件发送报告，并阅读自己的报告及开发者的回复；平台管理员阅读所有公司的所有报告，推进其状态并作出回复，每次变更都
记录由谁在何时完成。本单元是其自身数据的主人，数据保存在它自己的 SQLite 存储和附件文件夹中。`docs/design.md` 说明它是
什么，`docs/api.md` 说明它的边界：每条路由、它发布的事件、它发起的调用以及它的设置。其他所有单元都通过其 API 访问。

## 测试

`cargo test`(通过 testbed 运行)运行本 crate 唯一的测试框架 `tests/main.rs`：在回环端口上启动一个记录所收调用的账户服务
替身(stand-in)，并在临时文件夹中放置 SQLite 文件和附件文件夹，验证以下内容：连同文件整体发送或整体被拒绝的报告；只有
发送者本人和跨公司的开发者才能阅读的报告；带着历史记录在各状态间推进的报告；双方的回复；各方的未读计数；以内联或下载
方式交付的附件；每位读者收到的事件；控制台界面的守卫，以及按客户端引入的发行版用 bmo-ui 自己的读取方式读出的清单；
OpenAPI 文档；以及仓库自身的检查。

`client/` 包含自己的测试，在其中用 `bun test` 运行：四种语言(英语、韩语、日语和简体中文)的文案包在键和占位符上逐一
一致，界面写入的每个键和 `docs/api.md` 的每个错误代码都存在于每个文案包中，源代码中没有韩语，以及 API 模块在服务替身上的
调用。`client/tests/browser/` 在打包的开发主机和服务替身之上，以桌面宽度和手机宽度在真实浏览器中操作界面的两面。

## 目录结构

| 文件夹 | 内容 |
|---|---|
| `src/` | 服务及其命令：路由、调用者是谁以及站在哪一方、报告·附件·状态·回复·已读标记的存储及其迁移、对账户服务的调用、事件流、控制台界面的声明和 OpenAPI 文档 |
| `client/` | 控制台包：Nuxt 项目、引入的 bmo-ui 发行版以及安装时应用的组件库图层补丁、写出清单所指模块·样式表·文案·图层的构建、页面和组件、文案、自己的测试，以及在浏览器检查中代替控制台的开发主机 |
| `deploy/` | 服务的用户单元 |
| `docs/` | 关于服务是什么及其边界的规范文档，以及 OpenAPI 文档 |
| `tests/` | crate 唯一的测试框架及其所运行的对端替身 |
| `.graph/` | 代码图的设置；其区域文件由 `bmo graph` 生成，不纳入版本控制 |

根目录下有 Cargo 清单、`Cargo.lock`、`testbed.toml`、`install.toml`(在新机器上安装本单元所需的内容)、`rustfmt.toml`、
`settings.toml`(编入二进制的默认值)、`CLAUDE.md`、`PERSONAL-DATA.md` 和 `LICENSE`。
