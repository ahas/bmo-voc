# bmo-voc

고객의 목소리를 받는 창구입니다. 고객이 만든 사람에게 보내는 버그 제보와 제안, 그리고 만든 사람이 그것을 읽는 서비스가
여기에 있습니다. 콘솔에 로그인한 사람 가운데 플랫폼 관리자가 아닌 사람은 스크린샷과 파일을 붙여 제보를 보내고, 자기
제보와 그에 대한 만든 사람의 답을 읽습니다. 플랫폼 관리자는 모든 회사의 모든 제보를 읽고, 상태를 옮기고, 답을 달며,
바뀐 것마다 누가 언제 바꿨는지가 남습니다. 이 유닛은 자기 데이터의 주인이며, 그 데이터는 자기 SQLite 저장소와 첨부
폴더에 둡니다. `docs/design.md`는 이것이 무엇인지를, `docs/api.md`는 그 경계, 곧 모든 라우트, 내보내는 이벤트, 하는
호출과 설정을 말합니다. 다른 모든 유닛에는 그 API로 닿습니다.

## 테스트

`cargo test`(testbed를 통해 실행)는 이 크레이트의 단일 하니스인 `tests/main.rs`를 실행합니다. 받은 호출을 기록하는
계정 서비스의 대역(stand-in)을 루프백 포트에 띄우고, 임시 폴더에 SQLite 파일과 첨부 폴더를 두고 다음을 검증합니다.
파일과 함께 통째로 보내지거나 통째로 거부되는 제보, 보낸 사람 본인과 여러 회사에 걸친 만든 사람만 읽을 수 있는 제보,
이력과 함께 상태를 거쳐 가는 제보, 양쪽에서 다는 답, 각 쪽의 읽지 않은 수, 인라인이나 내려받기로 건네지는 첨부, 각
읽는 사람에게 주어지는 이벤트, 콘솔 화면의 가드와 클라이언트가 들여온 릴리스에서 bmo-ui의 읽기로 읽은 매니페스트,
OpenAPI 문서, 그리고 저장소 자체의 점검입니다.

`client/`에는 그 안에서 `bun test`로 실행하는 자체 테스트가 있습니다. 네 언어(영어, 한국어, 일본어, 간체 중국어)의
문구 팩이 키와 자리표시자까지 서로 맞는지, 화면이 쓰는 모든 키와 `docs/api.md`의 모든 오류 코드가 각 팩에 있는지,
소스에 한국어가 없는지, 그리고 서비스 대역 위에서 API 모듈의 호출을 검증합니다. `client/tests/browser/`는 번들의
개발 호스트와 서비스 대역 위에서, 데스크톱 폭과 휴대폰 폭으로 실제 브라우저에서 화면의 두 얼굴을 모두 움직여 봅니다.

## 구성

| 폴더 | 내용 |
|---|---|
| `src/` | 서비스와 그 명령: 라우트, 누가 호출하고 어느 쪽에 서는지, 제보·첨부·상태·답·읽음 표시의 저장소와 그 마이그레이션, 계정 서비스 호출, 이벤트 스트림, 콘솔 화면의 선언, OpenAPI 문서 |
| `client/` | 콘솔 번들: Nuxt 프로젝트, 들여온 bmo-ui 릴리스와 설치 때 적용되는 컴포넌트 라이브러리 레이어 패치, 매니페스트가 가리키는 모듈·스타일시트·문구·레이어를 쓰는 빌드, 페이지와 컴포넌트, 문구, 자체 테스트, 브라우저 점검에서 콘솔을 대신하는 개발 호스트 |
| `deploy/` | 서비스의 사용자 유닛 |
| `docs/` | 서비스가 무엇인지와 그 경계에 대한 기준 문서, OpenAPI 문서 |
| `tests/` | 크레이트의 단일 테스트 하니스와 그것이 위에서 도는 피어의 대역 |
| `.graph/` | 코드 그래프 설정. 영역 파일은 `bmo graph`가 만들며 추적하지 않습니다 |

루트에는 Cargo 매니페스트, `Cargo.lock`, `testbed.toml`, `install.toml`(새 머신에 이 유닛을 설치할 때 필요한 것),
`rustfmt.toml`, `settings.toml`(바이너리에 들어가는 기본값), `CLAUDE.md`, `PERSONAL-DATA.md`, `LICENSE`가 있습니다.
