# bmo-voc

お客様の声を受け取る窓口です。お客様が開発者に送るバグ報告や提案と、開発者がそれを読むためのサービスがここにあります。
コンソールにサインインした人のうちプラットフォーム管理者でない人は、スクリーンショットやファイルを添えて報告を送り、自分の
報告と開発者からの回答を読みます。プラットフォーム管理者はすべての会社のすべての報告を読み、状態を進め、回答し、変更の
たびに誰がいつ変えたかが残ります。このユニットは自分のデータの持ち主で、そのデータは自分の SQLite ストアと添付フォルダに
置かれます。`docs/design.md` はこれが何であるかを、`docs/api.md` はその境界、つまりすべてのルート、発行するイベント、
行う呼び出しと設定を述べます。ほかのユニットにはすべてその API を通じて届きます。

## テスト

`cargo test`(testbed 経由で実行)は、このクレートの唯一のハーネス `tests/main.rs` を実行します。受けた呼び出しを記録する
アカウントサービスの代役(stand-in)をループバックポートに立て、一時フォルダに SQLite ファイルと添付フォルダを置いて、次を
検証します。ファイルごと丸ごと送られるか丸ごと拒否される報告、送った本人と会社をまたぐ開発者だけが読める報告、履歴と
ともに状態を進む報告、双方からの回答、それぞれの側の未読数、インラインまたはダウンロードで渡される添付、それぞれの読み手に
渡されるイベント、コンソール画面のガードと、クライアントが取り込んだリリースで bmo-ui 自身の読み方により読まれる
マニフェスト、OpenAPI ドキュメント、そしてリポジトリ自身のチェックです。

`client/` には、そこで `bun test` によって実行される独自のテストがあります。4 つの言語(英語、韓国語、日本語、簡体字中国語)の
文言パックがキーとプレースホルダーまで一致すること、画面が書くすべてのキーと `docs/api.md` のすべてのエラーコードが各パックに
あること、ソースに韓国語がないこと、そしてサービスの代役に対する API モジュールの呼び出しを検証します。
`client/tests/browser/` は、バンドルの開発ホストとサービスの代役の上で、デスクトップ幅とスマートフォン幅の実際のブラウザで
画面の両面を操作します。

## 構成

| フォルダ | 内容 |
|---|---|
| `src/` | サービスとそのコマンド:ルート、誰が呼びどちら側に立つか、報告・添付・状態・回答・既読マークのストアとそのマイグレーション、アカウントサービスへの呼び出し、イベントストリーム、コンソール画面の宣言、OpenAPI ドキュメント |
| `client/` | コンソールバンドル:Nuxt プロジェクト、取り込んだ bmo-ui リリースとインストール時に適用されるコンポーネントライブラリのレイヤーパッチ、マニフェストが示すモジュール・スタイルシート・文言・レイヤーを書くビルド、ページとコンポーネント、文言、独自のテスト、ブラウザチェックでコンソールの代わりになる開発ホスト |
| `deploy/` | サービスのユーザーユニット |
| `docs/` | サービスが何であるかとその境界についての正典となる文書、OpenAPI ドキュメント |
| `tests/` | クレートの唯一のテストハーネスと、その上で動くピアの代役 |
| `.graph/` | コードグラフの設定。領域ファイルは `bmo graph` が生成し、追跡しません |

ルートには Cargo マニフェスト、`Cargo.lock`、`testbed.toml`、`install.toml`(新しいマシンにこのユニットをインストールするのに
必要なもの)、`rustfmt.toml`、`settings.toml`(バイナリに組み込まれる既定値)、`CLAUDE.md`、`PERSONAL-DATA.md`、`LICENSE`
があります。
